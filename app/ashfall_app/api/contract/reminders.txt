REMINDERS
  Off until the player turns them on. A browser with notifications on is one row, keyed by its Web Push endpoint. It holds
  two choices, either on alone: the absence reminder, one notification once the browser has been away the hours it
  picked, then none until it comes back; and the hands-free notice (below). Both routes are writes
  (csrf.py's rules hold), carry the endpoint only in the body, and answer Cache-Control: no-store; without a database,
  503 save_unavailable.
  /page-config.json names `reminders`: {public_key, after_hours: [int]} when the server can send them, null when it
  cannot (the page says reminders are not available here). A page that finds no `reminders` key at all is on a build
  from before reminders and offers no setting.
  ReminderOn {endpoint, p256dh, auth, tz, after_hours: int | null, send_from_hour: int | null, send_until_hour: int | null, hands_free: bool | null}
    endpoint, p256dh, auth  PushSubscription.toJSON()'s endpoint and keys. The endpoint must be https on a browser push
                   service (FCM, Mozilla, Apple, Windows), or 422.
    tz             the device's IANA time zone, or 422: the window's hours are local to it.
    after_hours    the absence reminder: one of page-config's reminders.after_hours; null, that reminder off.
    send_from_hour, send_until_hour
                   the notification times, one window for every kind: local hours 0-23, from up to until, past
                   midnight when from is later, any hour when they are equal. Both or neither. Sent whichever kinds are
                   on; the last sent stands, so the hours are kept while a kind goes off.
    hands_free     the hands-free notice on or off; null is off. Turning nothing on (no after_hours and no hands_free) is
                   422 (DELETE turns the browser off), as is one hour without the other. All four null refreshes a
                   browser already on (its keys and zone) and answers what it has on; 404 not_found when it is not on,
                   so the page shows the setting off.
  PUT /api/reminders -> Reminder {after_hours: int | null, send_from_hour, send_until_hour, hands_free}: the browser's
    row, made or changed; it becomes this account's whichever account held it, and counts as a visit. after_hours null:
    the absence reminder is off.
  DELETE /api/reminders, ReminderOff {endpoint} -> 204, whether or not it was on; another account's row is untouched.
  POST /api/saves/{id}/open and /advance mark the account's browsers visited (at most once per ten minutes); a
  reminder is due from the latest visit.
  The hands-free notice: one notification to each of the account's browsers with it on, when a long task the player
  gave the hands of the account's latest save (the most recently written, not deleted) is done and nothing they
  planned comes next (engine DESIGN.txt, "Forecast", Hands free), at a local hour inside the browser's notification
  times (a notice due outside them waits for the next run that finds them open, and is claimed only then; a browser
  outside its times when the claim is made gets none of that notice), unless the player gave that work less than
  reminders/hands_free.json's min_busy_s game seconds before, or the save was written at or after that moment (a page
  left open showed it). One per moment. The job forecasts the save after each decision and whenever the last forecast's
  reach has passed; it names no task, store or number.
